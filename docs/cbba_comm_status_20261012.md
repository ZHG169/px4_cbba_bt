# CBBA 機間通訊進度（2026-10-12）

無人機端 · 勝翔。範圍：cbba_node 和 cbba_node 之間的通訊（機間協定版本 2），以及 10/12 和機器狗端的介面對齊。

---

## 一、架構：機間通訊在哪裡

```
   無人機（每台一份）                                   機器狗 V60
 ┌───────────────────┐                          ┌───────────────────┐
 │ BT（行為樹）        │                          │ BT（伯宇的 task_manager）│
 └─────────┬─────────┘                          └─────────┬─────────┘
   機內 DDS │ current_task、robot_state、            機內 DDS │ 同一組話題、同一份訊息格式
           │ task_result、new_task                          │
 ┌─────────┴─────────┐   UDP multicast、協定版本 2   ┌─────────┴─────────┐
 │     cbba_node     │◄═══════ 經 mesh 網路 ═══════►│     cbba_node     │
 └───────────────────┘                          └───────────────────┘
```

- 每台跑同一支 `cbba_node`（`swarm_cbba` 套件，`agent_type` 區分無人機和狗）。
- DDS 只在機內；機間全走 UDP。這份報告談的是機間這一段。

## 二、協定版本 2

**為什麼改：版本 1 的限制**

- 用陣列位置當任務編號，全隊要先對齊「第 i 格是哪個任務」
- 機號超過 8 的載具（狗 50）不能建立任務
- 每台一輩子約 32 個任務
- 完成確認名單只有 8 個位元，狗不在裡面
- 重開機要存檔接續序號

**版本 2 的做法**：每筆任務資料帶 uint32 `task_id`（建立者機號 × 65536 + 流水號），各台自己維護對照；
重開機用每次啟動隨機的 `session_id`。20 B 表頭、大端序。**不相容於規格書**（要通知規格作者）。

| 封包 | 內容 | 頻率 |
|---|---|---|
| AGENT_STATE | 載具狀態、鄰居 | 每 0.5 s |
| CBBA_STATE | 得標者、出價、指派版本（任務多時分批） | 每 200 ms＋變動時 |
| TASK_ANNOUNCE | 任務定義 | 建立時、補發，轉送 |
| COMPLETION | 完成宣告 | 回報完成時，沒收齊每 1 s 重送 |
| COMPLETION_ACK | 完成確認 | 收到宣告時 |
| TASK_CLOSE | 任務結束（完成、取消） | 收齊確認、取消時，轉送 |

## 三、已完成的功能

| 功能 | 說明 |
|---|---|
| 任務擴散 | 轉送、去重複（滑動視窗）、缺的補發、開機同步 |
| 分配 | 共識後只有一台得標 |
| 完成確認 | 全隊確認後才結束任務 |
| 失敗交回 | 任務交回競標池；失敗的那台依 `reason` 排除 60 s 或永久 |
| 斷線接手 | PX4 斷線（停止參與）後撤銷，別台接手 |
| 重開機、晚加入 | 新 session，補齊全部任務 |
| 鎖定、指派版本、權限 | 執行中的任務不被搶走；擋掉舊回報；取消要建立者或授權機號 |
| 掉包容錯 | 30% 掉包仍收斂、不重複認領 |

## 四、測試結果（2026-10-12）

| 層 | 結果 | 說明 |
|---|---|---|
| 單元測試 | **167 項全過** | 零警告；通訊、指派測試各連跑 20 次無失敗 |
| 真 UDP 通訊測試（`itest comm`） | **8 / 9** | 3 台 docker 容器、走 mesh。未過的 C5 是還沒實作的失聯接手 |
| PX4 SITL 整串（`itest uav`） | **6 / 6** | 起飛、單一任務、火警、誘餌、三台分配與避碰、飛行中 PX4 斷線接手 |
| 狗端驗收情境 | **3 / 3** | 伯宇 README 的 T1、T2、T9 在我們的節點上照跑，結果一致 |

## 五、量測數據

| 項目 | 不掉包 | 掉包 30%、延遲 50±30 ms |
|---|---|---|
| 任務傳到全隊 | 約 12 ms | 0.45～2.2 s |
| 建立 → 指派給 BT | 約 0.4 s | 0.45～2.8 s |
| 回報完成 → 全隊確認 | 20～50 ms | 0.05～2.15 s |
| 失敗交回 → 別台接手 | 約 0.45 s | — |
| 停送狀態（PX4 斷線）→ 別台接手 | 1.9～2.6 s | — |
| 重開機 → 補齊所有任務 | 約 20 ms | — |

- 指派的 0.4 s 大部分是 `assign_hold`（等路徑第一位穩定，避免協商途中來回換手）。
- 掉包時慢在補發間隔 1 s（`resend_gap`）：掉一次就多 1 s。
- 斷線接手的約 2 s ＝ PX4 停送 0.5 s ＋ cbba_node 判斷逾時 1.5 s。
- 資料來源：10/11、10/12 的 `itest` 與手動 SITL 測試；掉包欄是範圍，視封包掉在哪一次而定。

## 六、和機器狗端的介面對齊（2026-10-12）

伯宇的 handoff 是對照 GitHub `dog-integration` 上 10/07 的舊程式（協定版本 1）。
決定：**BT 之間的格式照他的，機間協定和分配行為照 main（協定版本 2）**。他的 BT 不用改。

| 項目 | 改成（照伯宇） |
|---|---|
| 指派的話題 | `current_task` |
| RobotState | `mode`（AUTO／MANUAL／ESTOP），AUTO 才出價 |
| TaskResult | `reason`（PERMANENT 永久不接；其他 60 s 後恢復） |
| 指派版本 | 只在 cbba_node 之間用，BT 不帶 |
| 握手、ExecState | 拿掉，直接指派，BT 的哨兵負責中斷 |
| assign_hold | 0.4 s |
| 套件、啟動 | `swarm_cbba`、`cbba.launch.py`、`cbba_uav.yaml`／`cbba_v60.yaml` |

他會看到的分配行為差異（相對 10/07）：執行中的任務不會被搶走；處理火警時不排隊第二個火警（交給別台或做完再接）；
持有者斷線時執行中的任務先鎖著；只接受目前指派的回報；任務數量和建立者機號沒有限制。

## 七、測試中修掉的問題

| 問題 | 原因 | 修正後 |
|---|---|---|
| 飛行中 PX4 斷線，任務卡住沒人接 | 停止參與的節點不送紀錄，自己的撤銷傳不出去 | 照樣送紀錄（不送時間戳），約 2.4 s 別台接手 |
| 第 2 台起的 PX4 進不了自訂場景 | `px4_sitl.sh` 沒告訴 PX4 世界名稱 | 自動加入正在跑的場景 |
| 飛行狀態一直被誤判成無效 | `vehicle_status` 約 1.4～2.6 s 才一則，逾時只設 2 s | 改成 5 s，誤判從約 40 次降到 0 |
