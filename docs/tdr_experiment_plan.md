# TDR 參數實驗：規劃與執行方式

2026-11-16 · 依使用者的〈TDR 參數設定與測試計畫〉（PDF，6 頁）重新規劃；取代 `sim_scenario_plan.md` 第八節。
公式本身見 `ros2_ws/src/cbba_core/doc/formula/tdr_design.md`。

## 目的

決定兩組暫定參數，並確認它們在弱網下不會破壞 CBBA 的收斂：

| 參數 | 暫定值 | 決定什麼 |
|---|---|---|
| `energy_weight`（w_E） | 50 | 為了省電願意犧牲多少任務價值（用完可用電量 = 扣 w_E 分） |
| `half_life_by_priority` | P0～P3 = 60/120/300/600 s | 晚到多久會失去多少任務價值 |
| 狗的耗電模型 | 0.1 %/m＋0.05 %/s | 佔位值，等伯宇實測（階段 E） |
| 無人機 | 續航 900 s、存量 20 % | 模型輸入，不調 |

不能只用 TDR 總分挑參數（等於用模型自己的目標證明自己最好）：要用模型外的任務指標（P0 到達時間、耗電、返航餘量、
完成率、固定 half_life 的實際折扣價值）＋ CBBA 的穩定性指標一起判斷。

## 參數組

- w_E：0（對照）、25、50（暫定）、100、200（壓力測試）
- half_life：基準 [60, 120, 300, 600] s 乘共同倍率 γ ∈ {0.5, 1, 2}，保留 P0～P3 的相對急迫程度
- 第一輪 5 × 3 = 15 組，不掉包篩選；第二輪留 2～3 組（＋基準組）× 掉包 0/30/50/70 %，每格 100 次、同一組種子

## 情境（`cbba_core/src/tdr_experiment.cpp`）

每個情境只改一個主要因素；每個 seed 的幾何、電量、實際耗電誤差（±10 %）不同，但同一個 seed 在每個參數組、
每個掉包率都一樣（配對比較）。任務在 t0 = 3 s 之後插入（先讓節點完成開機同步）。

| 情境 | 設定 | 要回答 | 「該給誰」 |
|---|---|---|---|
| S1 時間差 | 兩隻狗離任務一樣遠、每公尺耗電相同、不算待機耗電；速度 0.7（機號 50）vs 1.5 m/s（51）；任務 P0／P1（seed 奇偶） | half_life 是否讓緊急任務給先到的 | 51（快的） |
| S2 能量差 | 兩隻狗速度、距離、耗電模型相同；電量 35 %（50）vs 90 %（51）；P2 | w_E 是否避開低餘量的載具 | 51（w_E = 0 時平手比機號，會給 50） |
| S3 時能取捨 | A：1.5 m/s、0.3 %/m（50）；B：0.7 m/s、0.08 %/m（51）；距離相同；P0／P3（seed 奇偶） | 臨界點在哪；P0、P3 是否有不同偏好 | P0 → 50、P3 → 51 |
| S4 路徑插入 | 狗 A 前往 25 m 外的 P3，5 s 後在旁邊插入 P0；狗 B 在 P0 的 25～50 m 外 | 插入位置、舊任務延後多少、P0 到達時間 | 沒有（看延後與到達時間） |
| S5 異質平台 | 1 架無人機（0.5 m/s、續航 900 s）＋1 隻狗；3 個平台不限的任務（P1～P3） | 平台成本是否造成合理差異 | 沒有 |
| S6 多任務機隊 | 3 架無人機＋3 隻狗（itest yard 的出生點）；12 個一般任務（無人機、狗、不限各 4，P0～P3，一半在 t0、一半在之後 120 s 內）＋一組 3 個角色（無人機 1、狗 2，distinct_agent_set） | 工作量是否集中、換手是否頻繁 | 沒有 |

bundle 上限照 cbba_node：無人機 2、狗 5；`assign_hold` 0.4 s。無人機的模擬電池照 PX4 依時間下降（待命也耗電），
狗依距離＋時間。

**和 PDF 不同、要知道的地方**

- S6 的角色組只用 `distinct_agent_set`（不同載具），沒有 precedence、會合、all-or-nothing：離線模擬沒有 BT 的 gate
  （那是 `swarm_cbba` 的 spec gates），也沒有閘道。協同的驗證留在階段 F（Gazebo）。
- 搶占時，被搶占的任務不算延後損失（`preempt_drops_head`，2026-10-12 的設計）：S4 的「是否算到延後舊任務的損失」
  答案是**不算**；S4 量的是實際延後多少，判斷這個設計可不可以接受。
- 實際折扣價值用固定的 half_life（基準 60/120/300/600 s），不是參數組自己的，否則 γ = 2 會自動拿到比較高的值。

## 指標（每次一列，`runs.csv`）

| 類別 | 欄位 | 定義 |
|---|---|---|
| 識別 | run_id、scenario、seed、trial、w_E、gamma、half_life_set、loss_rate | |
| 收斂 | converge_s、unconverged、conv_5s | 每個任務：插入後所有還在參與的節點都認得它、得標者一致、得標者的路徑上有它，持續 0.5 s；收斂時刻記這段一致的開始。converge_s 是最晚的那個任務；conv_5s = 全部 ≤ 5 s 而且沒有重複認領 |
| 重複認領 | duplicate、duplicate_time | 同一個任務同時有兩台以上的假 BT 在執行 |
| 換手 | handoff、handoff_unforced、preempted | 執行者換人的次數；前一位因失敗、返航、搶占停下的算被迫，其餘（重新競標）是 unforced |
| 分數差距 | score_gap、near_tie | 收斂當下第一、第二高出價的相對差（各任務最小值）；< 1 % 的任務數 |
| bundle 重建 | bundle_drops | 路徑上還開著的任務被拿掉的次數 |
| 任務品質 | P0_eta、P1_eta、deadline_miss、completed、discounted_value、choice_ok／choice_total | 到達時間從插入起算；期限違反只算有期限的任務（情境都沒給期限，應該一直是 0，留著當底線） |
| 能量 | energy_used、min_battery、min_return_margin | 耗電總和；過程中最低電量；結束時「電量 − 返航耗電 − 存量」的最小值 |
| 均衡 | max_tasks、min_tasks | 每台完成數 |
| 其他 | old_delay（S4 舊任務的延後）、wrong_accepts、end_time、winner_map | |

另外輸出 `tasks.csv`（每個任務）、`agents.csv`（每台）、`bids.csv`（收斂當下每台的出價分項：可行、插入位置、
估計到達、時間報酬、能量懲罰、邊際出價、是否得標）、`summary.csv`（每格的統計：5 s 收斂率、收斂中位／P95、
P0／P1 到達中位／P95、P5 最低電量、選對比例…；沒收斂的記 10 s，和 itest loss 一樣）。

## 入選順序（`scripts/tdr_report.py`）

1. 底線：期限違反 = 0、返航餘量 ≥ 0、完成率不比同一個 γ 的 w_E = 0 低超過 1 個百分點、不掉包時 5 s 收斂率 ≥ 95 %
2. P0／P1 到達時間：和基準組（50, γ 1）配對比較；P0 中位數在最好那組的 10 % 以內（`--eta-tol`）
3. 其中耗電最低的當正式值，次低的當備選
4. 弱網：候選組＋基準組在每個掉包率的 5 s 收斂率、收斂時間、重複認領、非被迫換手、分數平手率

報告另外列 S1～S3 的選對比例。結論句照 PDF 6.1 自動填數字，要人確認。

| 階段 | 內容 | 狀態 |

| B 公式單元測試 | `test_scoring`：w_E 變大出價不升、half_life 變短晚到的報酬不升、不可行一律 0；`test_tdr_experiment`（9 項）：S1～S4 的判讀方向、量測、可重現、狗的耗電、角色組不同載具 | 程式寫好，待跑 |

| E 狗端模型 | 伯宇實測的速度、耗電換掉佔位值，重跑入選組與邊界案例 | 等伯宇 |
| F Gazebo | BT、Planner、Registry 對接後：2 狗＋1 UAV 入侵角色組 | 等介面 |

```bash
# 編譯＋單元測試（照 CLAUDE.md，OUT 是暫存目錄；只列 cbba_core）
cd /out/build/cbba_core && ./test_scoring && ./test_mission_sim && ./test_tdr_experiment

# C：不掉包篩選（15 組 × 6 個情境 × 100 次 = 9000 次）
/out/build/cbba_core/cbba_sim tdr all --trials 100 --losses 0 --out /out/tdr_c
python3 ros2_ws/src/cbba_core/scripts/tdr_report.py /out/tdr_c

# D：弱網（例：候選 (25,1)、(50,1) → 跑兩次或用 --weights、--gammas 限定）
/out/build/cbba_core/cbba_sim tdr all --weights 25,50 --gammas 1 --losses 0,0.3,0.5,0.7 --out /out/tdr_d
python3 ros2_ws/src/cbba_core/scripts/tdr_report.py /out/tdr_d
```

`--jobs` 預設用全部 CPU 核心；`--bids 0` 可以不輸出 bids.csv（9000 次約數十萬列）。
驗證：挑入選組在 itest `loss --dogs 3` 跑（`--node-param energy_weight=…`、`half_life_by_priority=…`）。

## 定案表（實驗後填）

| 決策項目 | 正式值 | 備選值 | 依據 |
|---|---|---|---|
| energy_weight w_E | **25**（11/16 改成程式預設） | 50（原暫定值） | 和 50 比：P0 到達 −3.8 %、P0 P95 128 → 119 s、耗電 −2.9 %；S1～S3 全對；70 % 掉包 5 s 收斂 84.2 %（和 50 相同）、重複認領 51 vs 53 |
| P0～P3 half_life | **60/120/300/600 s（不改）** | 120/240/600/1200 s | γ 2 平手較多、70 % 掉包重複認領 60 vs 51 |
| 狗的耗電模型 | 待實測 | 0.1 %/m＋0.05 %/s | 定速、轉向、等待、感知執行的實測 |

## 限制

- 狗的速度、耗電是佔位值：第一輪只能說明公式與趨勢合理。
- 掉包只影響共識與收斂，不進 TDR；弱網結果變差時，用 `score_gap`／`near_tie` 區分「分數太接近」和通訊問題。
- 能力、期限、release、電量存量、bundle 上限是出價前的硬限制，不能用調 w_E 取代。
- 角色數量由 Planner／範本決定；TDR 只決定誰填哪個角色。
- 離線模擬是單一廣播域、一跳全連通、掉包在接收端各自獨立（和 itest 的「送出端掉包」不同），沒有頻寬限制。
